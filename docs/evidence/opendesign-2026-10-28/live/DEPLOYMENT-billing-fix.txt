What was wrong
--------------
The host reports one failed attempt through four channels (the retry hook,
session.step.failed, session.execution.failed, session.idle). Each recorded
its own strike, so one fault counted three times. The live ledger showed the
signature: three identical provider_outage entries in the same second.

A billing-scope failure is provider-scoped - it happens before a model is
selected and would hit every model on that provider equally - but it was
charged to whichever model was serving, so healthy models accumulated faults
they did not cause. The retry hook also dropped cooldownMs, so the hold-out
it recorded never engaged.
