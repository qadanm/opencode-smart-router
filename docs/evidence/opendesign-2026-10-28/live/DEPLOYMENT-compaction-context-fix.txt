What was wrong
--------------
An audit of the last 120 routing decisions found 9 that used a context size
the session no longer had - every one directly after a completed compaction,
with drifts from 97k to 472k tokens.

The context gate is contextTokens + 20,000 <= model.context * 0.95. OpenDesign's
328k window admits at most 291,600 tokens. A session compacted from 450k to 95k
still looked like 450k, so OpenDesign was excluded and the work continued on
OpenCode Go Plus - the pool that is 89% spent.

Two causes:
  1. The router never handled session.compaction.ended. The host emits it when a
     compaction completes and the router subscribes to the whole event bus, but
     there was no handler, so the pre-compaction value survived.
  2. The context size came from session.get().tokens, which is the session's
     CUMULATIVE usage over its whole life - 43M input and 2.9B cache-read on one
     session - clamped to 400,000. That clamp sits above OpenDesign's admission
     line, so it always excluded OpenDesign.

The fix
-------
Reads the real transcript size instead. A compaction message's own counts
describe the transcript it replaced, so the authoritative value is the last
assistant step, whose cache-read count reflects the rebuilt transcript. The
read costs 20-120ms even on the largest sessions, so admission waits for it
rather than guessing.
