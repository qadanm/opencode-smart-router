## What caused the disruption

1. OpenCode loads a global plugin **once per project location**. Commands and RPC are location-scoped.
2. A process-global singleton controller prevented duplicate routing but bound commands and RPC to the **first loaded project**, so they disappeared from the project the user was actually using.
3. Restoring one controller per project made the UI available again, but each location also ran session bootstrap and provider quota probing. With many open projects, this produced a burst of plugin loads and server work. The debug bundle showed **420 plugin loads** and repeated `server thrashing detected` warnings before the server restarted.
4. A previous controller could dispose its commands but hang while persisting, leaving a ghost controller that later loads reused. A healthy-state check fixed that specific ghost, but the per-location startup load was still too heavy to deploy safely without a shared core.

The debug bundle also contains an unrelated OpenRouter `QuotaExceeded` error for a session using OpenRouter. That is a separate provider-balance issue, not the Go/Command Code router.

## What was implemented and verified

- Persistent session-title indicator: `AUTO`, `MANUAL`, `PAUSED`, or `DRY RUN` plus provider and model.
- Visually verified in the actual desktop sidebar and tab:
  - `AUTO · Go · DeepSeek V4.1 Flash — …`
  - `MANUAL · Go · DeepSeek V4.1 Flash — …`
- `/router-title off` restores the original title; `/router-title on` reapplies it. Both were tested against the live desktop API.
- Manual model selection suspends automatic routing and changes the title to `MANUAL`.
- `/router-auto` clears the override and returns the title to `AUTO`.
- Native macOS notification path implemented using `terminal-notifier`, with an `osascript` fallback and duplicate suppression. The binary is installed; the plugin was disabled before a final live notification verification.
- Compact, token-free status view through the session title and RPC. `/router-status` uses OpenCode's synthetic UI message and does not call a model.
- 69 automated tests pass, including title formatting, manual/Auto transitions, title restoration, quota logic, routing policy, and controller integration.
- The model picker cannot show a real “Smart Auto” entry without registering a fake model/provider. That was not done. The supported 2.1.4 visual surface is the session title and native commands/RPC.
- OpenCode 2.2.0 has a GUI extension SDK; the installed 2.1.4 does not expose it for packaged user plugins. No app update was performed.

## Required next step before re-enabling

Rebuild the plugin as a **shared-core, per-location bridge**:

1. One process-wide core owns the ledger, provider quota cache, probing, and premium accounting.
2. Each project location gets a light bridge that registers commands, RPC, and a prompt hook, and calls the shared core with its own `ctx`.
3. No session bootstrap or provider probe on the startup path; poll in the background once per process.
4. Single-file install; test with a standalone OpenCode server and multiple project locations for a sustained soak before touching the desktop service again.
5. Re-enable only with explicit approval, then verify the default project’s commands/RPC and a prompt before leaving it live.
